# 会话列表刷新与插件启动等待优化（2026-11-04）

## 范围

本轮仅修改和验证本地前端。未提交、推送、部署或访问生产服务，未修改数据库结构和线上数据。此前各轮的本地修改继续保留。

## 已确认的问题与处理

### 1. 会话列表刷新存在平方级匹配开销

`SessionApi.applyChatsToSessionList()` 原来为每条服务端记录遍历旧列表，匹配后端 UUID 或本地临时 ID。即使返回的列表没有变化，也会先完成这一轮匹配，再进行内容比较。

- 使用真实 `getSessionList()` 路径、合成 API 响应进行复现：2,000 条记录触发 2,009,001 次身份读取；10,000 条触发 50,045,001 次，后者本地测试耗时约 1,166 毫秒。计数器会增加成本，不能将该耗时直接视为用户页面耗时。
- 使用修改前的构建页面及真实 Chrome 再测：10,000 条记录的一次后续刷新，从 JSON 解析完成到下一个事件循环任务约 593 毫秒，不包含网络等待。
- 现在每次刷新只建立一次 UUID/别名索引和未解析会话索引，再做匹配，匹配工作量从 O(n²) 降为 O(n)。候选项保留原顺序并只消费一次，避免临时 ID 或同一渠道下的多个会话互相覆盖。
- 保留原有列表排序、置顶、当前会话定位、同一 session_id 取最新会话、生成中状态、空白新会话保留及跨智能体请求隔离。
- 回归用例以工作量计数设上限，避免把受机器负载影响的绝对耗时作为 CI 判定条件。

### 2. 列表变化判断遗漏部分字段

原来 SessionApi 与侧栏各自维护比较规则，字段不一致。部分归档信息、会话寻址字段或共享权限变化，在标题和更新时间不变时可能被忽略。

现在共用 `areSessionListsEqual()`，统一比较列表需要的身份、时间、状态、归档、只读和分享人字段。内容相同时继续复用数组引用，避免无效刷新；消息历史仍由独立历史接口加载。

### 3. 没有前端插件也下载完整插件依赖

此前插件列表查询与完整宿主依赖加载同时开始，即使列表为空或只有后端插件，也需要下载完整组件和图标命名空间。

现在先检查插件清单，仅存在 `frontend_entry` 时加载完整宿主，宿主准备成功后才获取和执行插件脚本。完整插件 API 不删减。

清单发现与宿主准备共用原有 8 秒等待预算，避免改为顺序执行后将这一阶段延长到 16 秒。脚本下载仍有单独的超时；本轮没有宣称任意插件执行都能在 8 秒内结束。

## 工程约束

- 用临时索引降低匹配复杂度，没有引入长期会话缓存或新的状态事实源。
- 比较规则集中复用，避免两处规则再次分叉。
- 插件启动只调整依赖加载时机，保留公开插件接口和已有失败隔离。

## 验证与证据

相关前端 22 个测试文件、206 项测试通过，TypeScript、修改范围 ESLint、完整构建、Monaco CSS 和 `git diff --check` 通过。构建仍有已有的大文件及第三方循环依赖提示。

本地浏览器验证：

- 10,000 条会话的后续刷新，在同一计时方式下由约 593 毫秒降到约 11 毫秒；首次有效列表转换约 47 毫秒。该指标是 JSON 解析完成后到下一个事件循环任务的时间，包含该次页面处理，不代表完整 HTTP 耗时、所有设备或线上提速比例。置顶会话和列表深处的搜索结果均可见。
- 空插件及仅后端插件两个场景均没有请求 `hostExternals` 文件，也未初始化完整插件宿主。保留完整前端插件的合成样例仍能在 Chrome 中注册并显示路由，antd、图标和聊天扩展接口验证正常。
- 人为挂起插件宿主文件时，等待上限生效，基础页面继续显示；通知慢请求仍只有一个有效在途请求。
- 普通会话首批 5 轮、早期历史分页、管理员历史详情、2 MiB 工具输出按需读取和原始记录按需读取均通过，无页面脚本错误。
- 本地服务原先处于停止状态，已启动并就绪于 18089。健康、认证状态、版本接口正常；实际提供的入口 JS 与本轮磁盘构建逐字节一致。匿名登录、刷新和受保护深链接回到登录均通过。

业务浏览器验证使用合成 API，不调用真实模型；实际服务验证为匿名只读检查。后端本轮没有变化，没有将以前的后端测试结果列作本轮新增验证。

## 仍需区分的边界

1. 会话列表接口首次或变化后仍全量返回；本轮改善前端处理复杂度，没有实现服务端分页。服务端仍需要授权查询和完整运行索引拼装，不能把本轮结果当作该部分已经优化。
2. 插件脚本的无限顶层等待、同步长循环及跨身份迟到副作用仍需单独的隔离设计。本轮没有使用简单超时伪装成脚本取消。
3. 长正文 Markdown/代码块渲染、真实账号并发和生产网络耗时不在本轮测量结论内。
4. 本地验收入口为 http://127.0.0.1:18089/login；生产发布继续等待明确指令。
