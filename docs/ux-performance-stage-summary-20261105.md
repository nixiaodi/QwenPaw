# 用户体验与并发响应优化阶段总结（2026-11-05）

## 阶段范围

本阶段承接已发布的首屏、聊天历史分页和工具输出按需加载工作，集中处理登录及菜单迟缓、会话请求拥堵、消息队列发送权误判、长会话读取、列表全量加载及前端插件阻塞页面的问题。用户于 2026-11-05 明确授权总结、中文提交、推送和部署；此前优化和验证均先在本地完成。

本文描述本阶段最终实现。2026-11-04 各轮审计记录保留当时的进度和验证结果；其中“待实现”“等待上线”以及早期插件兼容方案不代表最终状态。严格 Worker 隔离以本文及 [迁移说明](frontend-plugin-worker-v1.md) 为准。

## 1. 后台监听与请求拥堵

- 文件监听不再长期占用 AnyIO 的共享工作线程。新增独立监听适配层，供根记忆、ReMe 和工作区监听复用，统一处理背压、取消与线程退出。
- 本地复现实验中，40 个旧监听占满 40 个共享线程，4.56 MB 文件响应约 10.03 秒；隔离后共享线程占用为 0，约 0.011 秒。60 个监听时仍未占用共享池。该结果解释了后台监听影响普通接口的原因，不代表线上所有接口具有相同比例的提速。
- 轮询改为统一调度：请求未结束不叠加，页面隐藏或离线时暂停，失败退避，取消后不再更新状态。工具卡片、后台任务和通知复用这些规则。
- 后台输出按短时间窗口合并渲染并限制保留文本量，减少大量输出引起的重复更新。

## 2. 消息队列与跨标签页发送权

- 发送权按账号、智能体和会话隔离，切换身份或卸载时释放旧资源。
- 区分正在申请锁、其他页面持有锁和浏览器锁异常；不再将空锁或接口异常统一显示为“由其他标签页发送”。
- 增加自动重试、页面重新可见时恢复及手动重试入口。发送组件尚未就绪时保留队列，发送前重新核对所有权、当前队首、暂停及错误状态。
- 迟到回调不能替新会话发送；队列保持去重和顺序。实际 Chromium 已验证单页恢复、多页互斥、锁异常、身份切换等 7 类场景，3 条不同消息均只发送一次。

## 3. 状态订阅、通知与竞态

- 计划、待确认输入及运行状态共享会话资源和事件订阅，合并重复请求；通过身份版本隔离切换账号或会话后的迟到响应。
- SSE 正常时减少回退轮询；流结束、断网和异常采用有上限的重连退避及连接超时，避免断开即重连造成请求风暴。
- 网络中断不再被当作任务正常完成。工具流和后台任务保留明确的异常、取消与重试行为。
- 控制台推送按作用域复用并引用计数，保持读取和消费通知的接口语义。收件箱读写、标记与删除操作处理取消和并发更新，身份切换清理旧通知。

## 4. 登录与基础页面加载

- 非当前语言、登录后的业务布局及内置工具卡片延迟加载；轻量插件注册入口与完整宿主实现拆开，登录页不再等待这些业务代码。
- 当前构建主入口为 1,620,888 字节，阶段初始约 4,561,243 字节，入口原始体积减少约 64%。这是主入口指标，不是全部资源总量或整站耗时的同比结论。
- 沿用经过验证的分包策略，避免通过未经验证的手工分包引入初始化顺序和刷新白屏问题。编辑器、图表等按需包仍较大，构建仍有体积提示。

## 5. 会话历史与大工具结果

- 保留最近 5 轮历史首批加载和向前翻页机制；合并摘要、历史及列表的重复请求，避免切换时旧缓存或旧响应覆盖当前身份。
- 新写入的外置工具结果保存带版本的有限摘要，首次历史读取直接使用摘要，展开后才读取完整输出。
- 合成测试中，10 份各 2 MiB 的结果首次加载完整载荷读取为 0 次、0 字节；展开一项后只读取该项。旧记录仍有兼容回退，不能宣称所有历史数据都已经转换为新格式。
- 管理员详情继续使用聊天式只读展示，完整工具输出与原始记录按需请求。

## 6. 会话列表真正分页

- 新增 `/api/chats/page`，默认每页 20 条、最大 100 条，返回 `items`、`has_more` 和 `next_cursor`。侧栏、会话抽屉和会话管理按需加载，管理员全部会话使用数据库游标分页。
- 标题搜索、归档、频道、用户及 owned/shared 范围在服务端处理，可搜索尚未加载的历史记录。按置顶、更新时间和 ID 稳定排序；管理员游标保留精确微秒时间。
- 游标绑定身份、智能体和筛选条件，每页重新核对数据库授权；运行索引缓存不缓存授权结论。
- 文件索引按文件标识、大小及时间失效，首次解析与排序移至工作线程；二分定位游标，授权候选分批处理，避免每页投影全部会话。
- 相同在途请求复用，单个读者取消不影响其他读者；仅刷新已加载页，不自动遍历全部历史。错误保留已显示内容并允许重试。
- 旧 UUID 链接通过单条元数据接口打开，临时链接通过精确 `session_id` 解析，避免会话不在第一页时被误判不存在。删除其他会话不再跳走当前深链接。
- 10000 条合成会话浏览器验证：首次 20 条、继续加载再 20 条，搜索列表深处记录成功，页面未调用旧全量列表接口。旧接口保留兼容；没有将运行索引整体迁移到数据库。

## 7. 前端插件严格执行隔离

- 按用户选择实施严格策略：插件必须声明并适配 `entry.frontend_runtime = "worker-v1"`。旧前端插件明确提示升级，停止自动下载和执行，不回退主线程。
- 插件导入、渲染和事件处理在独立 Worker 内运行；主页面仅接收校验后的有限界面数据，不执行插件注入的 React 组件或回调。
- 初始化、渲染、代理网络请求设有超时、数量及数据上限；超时终止 Worker，心跳检查持续同步阻塞；账号切换清理旧线程和注册项。
- 基础菜单、登录和聊天页面不等待插件初始化。正常插件可使用数据式路由、工具卡片、按钮及受限的后端请求接口。
- Chromium 覆盖旧插件拦截、初始化死循环、无限顶层等待、正常交互和渲染死循环。相同 2.5 秒同步循环在旧主线程执行时最大计时间隔约 2518 毫秒，在 Worker 下约 226 毫秒。
- 本轮隔离的是前端执行；后端插件继续遵循已有治理规则。Worker 不是操作系统或恶意代码安全沙箱。迁移需改造实际接口，不能仅修改清单声明。

## 8. 会话误删保护

- 共享会话条目增加包含标题的二次删除确认，默认聚焦取消；只读会话禁止删除，防止重复弹窗，切换账号、智能体或卸载后不执行旧确认。
- 早期丢失会话调查记录见 [诊断说明](conversation-deletion-diagnosis-20261023.md)。按用户“暂时不恢复”的要求，本阶段未恢复会话、修改删除标记或重写消息数据。

## 发布和兼容边界

- 从提交后的源码与本次构建生成白名单发布包，逐文件 SHA-256 校验；不包含本地配置、数据库、凭据、TLS 证书或用户文件。
- 沿用当前镜像依赖构建候选镜像，校验安装目录和应用源码目录两份代码。仅切换 `agent-app`，数据库和模型代理不重启。
- 等待真实运行任务结束，使用现有维护锁排空操作，备份数据库、应用源码与配置后切换；失败恢复原镜像、Compose 和同步源码。
- 数据库仍为 `0021_skill_public_admin_read`，无需结构迁移。不清理历史备份，不恢复或批量变更线上会话，不修改用户工作区。
- 发布后的实际镜像、备份路径、线上验证和回滚信息另记于发布验收文档。真实网络抖动、大型 Markdown 持续渲染、运行索引高频变动及多用户峰值仍需持续观察。

## 实现原则

统一轮询、分页请求、会话资源和 Worker 协议以减少重复逻辑；将线程生命周期、分页授权与 UI 渲染分别封装，保持单一职责。保留现有接口兼容与存储模式，没有为本轮性能修复引入新的基础服务或数据库迁移；只实现已经确认的严格插件接口和必要容量限制。
