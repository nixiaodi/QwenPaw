# 用户体验与请求拥堵检查

日期：2026-11-04。范围：登录后的通知、侧栏、会话列表、工具执行卡片、后台工具状态和插件初始化。延续“本地修改、验证、用户验收后再发布”的约定；本轮没有访问或修改生产环境，没有提交、推送、部署。

## 已复现并在本地修复

### 工具执行卡片在慢接口下放大请求量

`useToolCallControl` 原来同时启动每 250 毫秒的初始化重试与每 2 秒的状态轮询。上次请求未完成时仍继续发起下一次请求。用真实 hook、延迟不返回的状态接口测试，单个工具 5 秒内发出 23 次状态请求；多个执行卡片会进一步放大负担。

合并为单个调度流程：一轮完成后才安排下一轮，状态接口通常间隔 2 秒；新会话的后端 ID 尚未生成时保留 250 毫秒的本地映射检查。任务停止或组件卸载时取消请求，忽略过期响应。相同测试下状态请求降为 1 次，策略请求也仅 1 次。倒计时、转后台、普通完成与快速后台完成的原行为有回归覆盖。

### 通知和后台状态轮询叠加

全局通知每 2.5 秒、侧栏每 6 秒、后台工具降级轮询每 3 秒发起请求。原先均可能在慢请求尚未结束时继续查询。

通知组件单独复现为 10 秒内 5 次请求；后台工具复现为 12 秒内 4 次。修复后各自最多保留 1 个未完成的轮询请求。侧栏的两个并行查询等待双方结束后再调度，避免其中一方先失败、另一方仍在等待时重新叠加请求。

### 页面不活动时仍持续刷新

会话列表和侧栏徽标改为页面隐藏时暂停、恢复显示时立即刷新；全局通知、工具控制和后台任务保留每 30 秒的后台检查。浏览器离线时暂停这些轮询，恢复联网时刷新。失败后逐渐延长间隔，最长 30 秒；成功后恢复正常频率。

这是有意的体验取舍：后台页面的通知更新可能比以前晚，前台操作获得更多请求资源。正在执行的服务端任务不会因此停止；工具流连接的正常实时更新继续工作。

### 网络断开被错误显示成任务完成

发现并复现两条路径：

1. 后台状态查询遇到任何异常，都按“任务已完成”处理，甚至显示完成提示。
2. 工具 SSE 连接没有收到 `done` 事件，只要连接结束，也按完成处理。

现在网络错误保留运行状态并退避重试；提前结束的 SSE 转入状态查询，只在明确完成事件或后端状态确认后结束。保留既有 404 后读取最终输出的兼容逻辑。离开会话后，迟到的工具回调不再继续拉取结果或更新任务状态。

### 插件请求没有期限，拖住整个应用初始化

`AppInner` 在插件初始化完成前等待。插件列表和脚本下载原来使用无超时的 fetch，因此网络不结束时，页面可以一直显示初始化状态。

插件列表和每个插件脚本的网络读取现在各有 8 秒超时，覆盖响应正文读取；失败记入插件加载结果，结束相应等待。用户切换或卸载时取消未完成的插件请求，旧用户的迟到响应不能解除新用户的加载状态。

完整页面验证还发现初始化顺序问题：认证启动时的临时 legacy 状态会提前触发插件请求，认证完成后再触发一次；业务页面在插件 effect 设置 loading 之前短暂挂载，然后立即卸载。新增两项失败测试确认该行为。现在先确定认证状态再加载插件，并根据当前用户的加载完成状态同步控制页面挂载，消除这条重复启动路径。

边界：这约束的是插件网络下载，不是任意第三方脚本的执行时长。已经执行的第三方插件若阻塞浏览器主线程，仍需单独定位，不能声称本次已为任意插件建立执行沙箱。列表与脚本分别限时，不等于整个初始化总耗时保证为 8 秒。

## 后续本地优化：首屏、会话列表和工具输出

用户随后授权继续本地优化。本节为在前述 137 项回归基础上的追加实现；没有提交、推送、部署或修改线上数据。

### 首屏加载

- 中文和英文保留同步资源，其余五种语言通过动态导入按需加载，采用 i18next 的 `partialBundledLanguages` 后端机制，不添加依赖。区域语言代码和巴西葡萄牙语均有回归覆盖。
- 初始化等待所选语言就绪，期间保留 HTML 中的加载提示。可选语言包下载失败或超过 8 秒，使用英文回退，避免无限等待。
- 业务布局和内置工具卡片在认证通过后才加载；普通界面和桌面界面共用初始化逻辑，使用已有分包重试及错误边界。外部插件对工具卡片的覆盖优先级保持有效。
- 保留 Rollup 默认依赖顺序，没有重新引入曾导致白屏的手工 vendor 分包。

### 会话列表重复传输与查询范围

- `/api/chats` 使用弱 ETag 和 `private, no-cache`，由浏览器进行条件请求。每次仍先重新查询用户权限、会话信息和运行状态，随后决定返回完整列表还是无正文的 304。
- 响应声明 `Vary: Authorization, Cookie, X-Agent-Id`。切换智能体、改名、运行状态变化和共享权限撤销均覆盖验证；不将旧列表当作离线授权依据。
- 数据库查询增加当前智能体过滤；共享成员 JOIN 限定当前用户，避免所有者的会话因多个共享成员而生成重复查询行。排序增加会话 ID 作为相同时间戳下的稳定次序。
- 使用真实列表处理函数、5,000 条合成数据和未拦截网络的 Chrome 验证：首次正文 2,032,781 字节，未变化时重复请求正文为 0 字节；状态变化后重新返回 200，切换到单条会话的智能体返回 1 条，撤销权限后返回空列表。
- 浏览器可能带着旧验证标签请求另一个 `Vary` 组合，因此验收检查实际返回的列表与状态，不假定换智能体必然不发送 `If-None-Match`。服务端对当前授权结果重新计算摘要，不能以请求标签直接跳过权限检查。

### 高频后台工具输出

- 后台工具 SSE 输出在 50 ms 窗口内合并再更新任务状态。原先 1,000 个连续片段产生 1,000 次 store 通知；对照测试现在合并成 1 次。
- 缓冲区和已有展示上限一致，最多保留最后 80,000 字符。完成、取消、进入轮询和停止监听时刷新缓冲；会话离开后清除计时器，迟到片段不能污染新会话。
- 覆盖正常完成、最终输出接口不可用时保留末尾内容、大于上限的输出、取消和会话切换。该优化针对后台工具任务，不声称已优化第三方 SDK 的所有正文 Markdown 渲染。

## 尚未消除的性能边界

2026-11-04 后续复核新增并完成了聊天面板单请求轮询与身份隔离、状态 SSE 退避、新工具载荷摘要读取；当前累计相关回归为前端 171 项、后端聊天 198 项。详见 [本轮修复与剩余问题](remaining-ux-audit-20261104.md)，下列结构性边界仍然存在。

1. **公共入口仍较大。** 插件宿主仍同步暴露整套组件和图标，主入口约 3.45 MB。继续拆分需要验证第三方插件的初始化契约，本次没有修改这一公开接口。
2. **静态资源服务路径。** 后台监听与 HTTP 工作线程已在本地隔离；Nginx 直接提供构建产物尚未实施，需要结合发布目录、缓存和版本切换单独验证。
3. **首次及变化后的会话列表仍为全量。** 本次减少未变化的重复传输和跨智能体查询，没有引入列表分页，也没有截断搜索、置顶、分享和定位所依赖的完整列表。304 仍需权限查询、序列化和摘要计算，不能视为数据库成本归零。
4. **真实模型长流与用户设备负载。** 后台工具输出的更新频率已降低；第三方聊天 SDK 的超长 Markdown/代码块逐片渲染、线上并发及用户设备实际长任务尚需性能记录。当前测试范围未复现白屏、重复历史请求、队列单页失去发送权和轮询堆积，但不能宣称所有场景已不再卡顿。
