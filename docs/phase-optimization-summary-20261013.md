## 二、会话归属、加载与交互稳定性

### 1. Chat not found 与智能体切换

已确认的报错会话仍存在，并可在所属智能体下读取；用其他智能体上下文访问返回 404，符合既有访问隔离。根因是路由、当前智能体选择、会话恢复目标及传输身份未同步：从技能或设置页面返回聊天时，旧链接可能反向覆盖用户已明确选择的智能体；聊天页未挂载时，其 effect 无法清理旧恢复目标。

当前实现：

- 侧栏各布局统一携带当前智能体的导航意图。
- ChatRoute 在未知深链接中从用户可访问的智能体列表解析归属；显式切换或返回智能体页面时，只恢复当前智能体可访问的会话。
- 不匹配期间暂停挂载 ChatPage；旧异步解析结果在上下文变化后失效。
- SessionApi 在统一切换入口同步清除 preferred、lastActive、lastNavigated 和窗口传输身份，无需依赖聊天组件是否挂载。
- 找不到当前智能体的有效旧目标时进入新聊天，而不是请求旧智能体会话。

修复沿用服务端会话权限，没有移动、删除或重新分配用户会话。

### 2. 会话加载速度与新聊天闪动

后台首次返回会话 UUID 时，旧路由将聊天组件替换为加载 Spin，造成卸载、再次挂载和输入状态丢失。现在对已由当前智能体 POST 响应确认的活跃会话 ID 保持 ChatPage 挂载；未知深链接仍进行归属解析。

已知归属的导航直接使用当前智能体信息。未知深链接的并行查询在找到匹配后立即完成，不等待无关智能体的慢请求。回归覆盖无关请求一直未返回时仍可打开匹配会话，以及首条消息取得 UUID 后组件只挂载一次、输入保留。

历史本地样本含 208 条消息，历史接口实测约 95–287 ms。这是当时的响应样本，不是修复前后的性能对比，也不是对全部会话加载时间的承诺。

## 三、认证、模型可用性与智能体创建

多标签页共享刷新 Cookie，但刷新会同时轮换访问与刷新令牌；旧实现没有协调，另一个标签页的请求可能使用已失效令牌。前端现对刷新、登录、注册、退出和启动身份恢复使用同源 Web Lock，身份查询位于刷新锁内；BroadcastChannel 同步内存令牌、退出和账户变化，切换身份时清理用户作用域缓存。

自动化测试覆盖锁、广播和缓存清理；线上认证接口记录覆盖匿名拒绝、串行刷新、身份查询、退出失效及 HTTPS Cookie 属性。尚未完成用户登录后的同一浏览器双标签页真实交互验收；浏览器缺少 Web Locks 或 BroadcastChannel 时存在兼容回退，不能声称所有浏览器均具备相同协调能力。

模型管理原先通过清空 API Key 模拟禁用，对无需 Key 的供应商无效，也可能被空字符串更新规则忽略。当前为供应商和模型加入独立、持久化的 enabled 状态：

- 管理界面保留原配置和凭据，支持重新启用。
- 可选模型目录、模型选择 API 和有效默认模型解析共同检查启用状态。
- 刷新模型列表保留已有模型的禁用状态。
- 禁用正在使用的默认配置时明确返回不可用原因，不自动换用其他模型。

发送前检查原先把任意接口异常都显示为“模型未配置”。现在请求错误保留 HTTP 状态和原始原因；只有实际缺少默认模型时显示配置提示。历史服务器验证时，八个智能体的默认模型均可正确解析，部分免 Key 供应商禁用后不再进入可选目录，重启后状态保留。

新建智能体界面固定使用原生 qwenpaw 后端，直接填写智能体信息，移除新建流程中的第三方执行后端选择；已有智能体编辑继续兼容原配置。

## 四、附件、产物、文件引用与预览

### 1. 会话附件恢复与 @ 引用

新增 ConversationAttachments，从服务器恢复当前对话上传文件的数量和列表，点击进入既有文件预览。上传或执行状态变化后刷新，按智能体、会话及请求版本拒绝过期结果，离开再进入后仍能恢复列表。

@ 文件候选扩展到文档和图片产物。PDF、Office 等文档复用个人资料库已有正文提取器；图片返回鉴权后的本地查看提示。目录发现和实际读取仍检查用户、智能体、附件生命周期和安全路径，不将客户端路径当作文件访问权限。

### 2. 下载地址以真实交付为依据

已确认的历史报告存在且可下载，但助手最终文本编造了另一地址。send_file_to_user 现在向多用户会话返回登记产物的站内下载地址；前端从本轮成功工具结果提取文件名与真实链接，为能唯一匹配的下载文本使用鉴权下载，解码中文文件名。

历史 sandbox:/mnt/data 链接只转换为文件名引用。点击时按当前用户、智能体和对话查询已登记的 active 产物，同名文件取该对话最新版本；没有记录时明确提示。它不会把 sandbox 路径映射成服务器任意路径，也不会从其他对话借用同名文件。无关外部资料链接继续按原链接处理。

内网部署文档补充同源 /api 预览与下载、HTTP 内网刷新 Cookie 设置、HTTPS 切换以及不同账户的私人文件验收步骤。localhost 可用不能证明普通内网 IP 的 HTTP Cookie 行为相同。

### 3. 发送前验证与防止虚假完成

新增独立产物验证：拒绝空文件；PDF 检查可解析页及内容；常见图片检查可识别性；DOCX、PPTX、XLSX 检查必要 ZIP/XML 结构。失败返回工具错误，不发布成功链接，保留源文件。该验证检查文件格式有效性，不代替合同内容、报告质量或完整业务输出验收。

公共运行时增加文件交付、图片生成和检索证据组件。明确生成格式要求依赖本轮成功发送对应类型文件；检索要求实际成功执行检索工具，加载技能或执行 --help 不构成成功检索。证据由工具中间件观察，不依赖会被 Scroll 压缩的模型上下文，也不接受上一轮证据。缺少证据的完成文字先缓冲，有限补执行后仍未成功时明确报告未完成，并修正模型已保存的虚假完成消息。

图片专用证据组件区分实际 image_gen.py 执行与 --dry-run；当前通用图片请求的 FileDeliveryGuard 主要校验真实图片交付。新版 imagegen 指令另外要求真实文件、尺寸检查和发送，不能把干运行视为已出图。

### 4. 多用户图片预览 403

上传路径曾按智能体编辑角色分支：普通使用者进入个人目录，所有者和协作者进入公共智能体 media；预览接口却仅允许个人 user_workspaces，导致同一图片附件下载成功、工具路径预览返回 403。

现在所有多用户上传统一按可信上传者和智能体解析个人目录，上传及附件保存共用目录规则。旧智能体 media、documents 或历史中文资料目录中的文件，只有实际路径、当前用户、智能体及有效附件记录匹配时才允许读取。保存、移动和删除保留上传者身份校验，符号链接与 Windows junction 在路径解析前拒绝。

本地已用报告的两张原图及八个启用智能体逐项验证上传、预览、下载、保存和保存后预览；本人成功，其他用户拒绝，匿名请求拒绝。没有按会话 ID 或文件名添加特殊放行。

另有独立限制：freeze_local_image 仍限制模型读取的图片不超过 2,097,152 字节（2 MiB）。其中一张原图为 2,412,788 字节，超出该限制；本次修复没有提高上限。浏览器预览成功与模型能否直接读取该图片是两项不同的验证。

## 五、工具运行状态与失败提示

Shell 非零退出及执行异常现在标记为错误。运行结束时，Runtime 在最终响应发送前按服务端可信用户身份清理运行状态，同时保留异常、取消路径的收尾，并避免影响其他用户的状态。

实时工具面板仅在当前对话运行期间显示。完成或停用使旧轮询失效，状态请求使用版本号及会话身份校验，避免旧失败结果在完成后重新覆盖界面；其他会话的事件不能更新当前面板。历史消息中的工具错误仍保留。

验证覆盖真实失败工具调用后会话 idle、运行状态为空，以及完成后旧轮询返回失败、其他会话只有 session_id 等竞态。POSIX 端口预检另外修正 TIME_WAIT 被误判占用，真正活动监听仍拒绝启动，Windows 保留原有检查方式。

## 六、记忆作用域、通知与自动召回

手动记忆使用当前用户在当前智能体下的私有 ReMe 运行时，来源会话贯穿调用和收件箱事件。记忆文件定位依据执行前后的真实文件变化，不采用模型“已生成”的措辞作为证据。

/memorize 等待任务结束后返回实际结果，并兼容 /mermorize。成功、无新增文件、运行失败都有明确反馈；手动操作可收到完成通知，失败路径避免重复通知。无实际写入时说明没有更新记忆文件，而不是附上虚构文件路径。

公共定时记忆任务按智能体当前所有者重新解析用户状态、智能体状态和模型授权，不继承某个历史会话身份。无法确认当前授权时终止执行。

用户报告的查询会话实际已自动命中两份 [my_memory] 文件并注入模型输入；此前没有工具事件，因此 SSE、数据库历史和聊天页面看不到自动检索。MemoryMiddleware 现在将已完成的真实检索转换为标准工具调用和结果事件，在模型输出前沿现有 SSE/持久化链路展示：

- 不额外重复检索，不改变长期会话上下文。
- 同一回复的后续推理不重复发送。
- 无命中、上一轮缓存和自动化请求不冒充本轮召回。
- 中英文提示统一要求实际使用记忆时简短说明来源；时效信息先参考记忆，再核实当前来源。

本地真实模型、HTTP 和 PostgreSQL 回读验证了记忆命中进入模型输入、先显示 memory_search、之后核实外部来源，历史仅保存一条该轮自动检索结果。用户原始会话没有被重写；个人记忆按用户和智能体隔离。

## 七、技能发现、加载与治理发布

### 1. 当前最终加载契约

10-08 曾通过运行时自动注入正文解决漏路由；后续 10-09 按用户预期改为渐进加载。当前模型先看到已启用技能的名称和描述，比较任务后调用 load_skill 读取当前正文，运行时不为自然语言请求指定某个脚本或提前注入全文。

load_skill 由 ToolResponse 改为当前适配层支持的 ToolChunk，保留结构化 JSON、目录说明和失败状态。技能加载中间件在要求技能的任务中阻止未成功加载即执行；脚本引用另一技能目录时也检查对应技能加载。显式技能命令保留用户选择，但同样需要调用 load_skill。

业务分类补充合同、新闻、创作者、标讯检索和投标编写，识别连字符名称，减少“报告”等泛词导致的格式误路由。自然语言候选歧义交由看到完整启用目录的模型处理；/skills 和详情等信息命令由公共运行时响应。

多轮“继续”“确认”通过真实会话 mode_state 保留整体任务与已选技能，成功交付后清理待办状态，禁用技能不能从旧状态恢复。大纲或审批步骤不会被当成已交付完整文件。迁入技能的 WebSearch、WebFetch 和 AskUserQuestion 角色提示映射到当前可用工具，缺少工具时明确说明阻碍。

技能卡片将来源操作与普通动作分开布局，预留底部操作空间，减少悬停时的布局跳动和覆盖。

### 2. 草稿刷新与共享快照

技能池刷新检查本地草稿和 SKILL.md，计算草稿哈希时允许包含私有配置，不把“可预览草稿”误判成“可共享发布”。共享发布仍经过 import_existing、快照捕获和凭据扫描。

共享包默认拒绝运行时 manifest、环境文件及证书/私钥等私有文件。根目录 skill.json 仅在符合严格的公开描述元数据结构时允许：限定字段与类型，不能放行运行时配置；捕获和验证仍执行凭据扫描。旧不可变快照不直接改写。

迁移技能的文档与创作者依赖补入部署依赖文件，容器补充 Poppler、LibreOffice Writer/Impress 及必要 Python 库，使相关能力在部署时有明确依赖依据。仅检查未启用技能的库存、元数据和脚本语法，未擅自启用有外部副作用的技能。

## 八、个人频道、Slash 与 Apps

频道页面固定为“我的频道绑定”，展示钉钉、飞书、微信、企业微信和 QQ。其他连接器从本界面隐藏，已有配置没有删除。

绑定凭据和所有者从已认证用户派生；同一智能体、同一频道类型可由不同用户分别配置。监听器按 binding_id 启停，频道请求在执行前重新验证绑定所有者、智能体使用权限与模型授权，保留外部回复目标并复用 PostgreSQL 会话消息持久化。

过去监听器仍共用智能体工作区。现在缓存、媒体及微信凭据文件进入：

```text
user_workspaces/{user_id}/{agent_id}/channels/{binding_id}
```

每个绑定只构造目标连接器，关闭无关默认 console。双用户同一智能体与同一频道类型的配置、启停及目录隔离已有测试；五种实际连接器的路径派生及本人/他人预览授权也已验证。没有向真实平台联系人发送测试消息，平台账号联网、实际收发和推送尚未验收；多个用户复用同一真实 Bot 仍可能受平台抢连接或重复投递规则影响。

Slash 无图标项此前少了 18px 图标槽及 8px 间距，命令标题提前 26px。现在所有候选保留统一图标槽，沿用已有布局，未改变过滤、键盘交互和命令执行。相关测试通过，但没有完成浏览器像素或可视回放验收。

Apps 本阶段只做机制分析：

- PawApp 是含 manifest 和前后端入口的业务插件，可增加页面、API、工具、技能、命令或后台任务；仅有页面的应用不会自动增加聊天能力，注册聊天工具后还受智能体工具启用配置控制，工具默认禁用。
- 共享应用是经过审核发布的智能体版本，固定模型、技能、插件和 MCP 等依赖；每个使用用户有独立会话和版本工作区。
- 安装应用不等于每个智能体都能调用其全部能力；第三方应用自身业务数据的用户隔离仍需按具体实现单独验证。

## 九、imagegen 新版高质量策略与可复现归档

调整前安装脚本真实默认为 gpt-image-2 / medium / auto。本次技能包改为：

| 场景 | 当前策略 |
| --- | --- |
| 默认生成 | gpt-image-2.5-sunburst，xhigh |
| 用户明确要求速度优先 | Flare；未要求降质量时保留高质量和高分辨率 |
| 16:9 / 9:16 | 3840×2160 / 2160×3840 |
| 默认方图 | 2880×2880，处于既有像素上限内 |
