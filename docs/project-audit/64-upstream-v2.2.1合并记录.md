## 多用户兼容结论

当前平台在同一个服务和 PostgreSQL 身份域中承载多个用户与多个智能体。用户、智能体、会话、文件、知识库、产物、记忆、技能、插件、模型、自动化和审批都由平台统一授权和审计。合并过程中继续以这些边界为准，没有使用上游单用户实现覆盖当前业务域。

重点保留的当前实现包括：

- 登录、用户管理、管理员重置密码和个人资料维护；
- 智能体归属、共享应用授权和默认模型继承；
- 聊天会话恢复、浏览器标签切换、消息去重和流式状态收敛；
- 统一文件中心的临时附件、个人资料库、产物、Agent 配置和记忆五类内容；
- 个人资料库的用户隔离、文档解析和对话检索；
- 记忆的用户与智能体双重作用域；
- 技能池的管理员发布、Agent 授权、广播和普通用户申请审批；
- PostgreSQL 中的会话、MCP、自动化、审批和资源归属关系；
- 多用户备份恢复范围及密钥处理。

## 有意未合入或未启用的内容

### QwenPaw Hub

QwenPaw Hub 为每位用户创建或管理独立运行实例，拥有自己的登录态、运行时生命周期、工作目录和控制面。当前平台已经在一个服务中实现多用户身份、资源授权与审计，如果同时启用 Hub，会形成第二套用户空间和运行时控制面，并绕开现有数据库授权关系。

因此不合入以下内容：

- Hub 后端、Hub 页面、Hub API、Hub CLI 和 Hub 测试；
- Hub 本地实例或容器生命周期管理；
- Hub 身份令牌向本地运行时的转发逻辑。

如后续确需 Hub，必须先设计 Hub 租户到现有用户、智能体、文件、知识库、记忆和审批表的唯一映射，不允许直接旁路部署。

### 新记忆后端迁移

上游 `v2.2.1` 增加 Auto Fin，将 ReMe 升级到 `0.4.1.11`，并把 ADBPG、PowerContext 改为插件。当前平台的自动记忆、Dream、记忆文件展示与检索依赖 ReMe `0.4.1.5` 的组件生命周期，并已经增加用户与智能体双重作用域。

本次保留通用插件接口升级，但不打包或启用 ADBPG、PowerContext 插件，也不启用 Auto Fin，不升级 ReMe。这样可以避免在正式版本中出现未经多用户授权模型约束的第二套记忆存储。相关上游发布说明已增加本分支差异提示。

### 控制台整体改版

没有整体替换上游侧栏、Settings Center、聊天会话 Store 和文件页面。当前页面已经包含多用户菜单、文件中心、跨标签恢复、重复消息治理和路由恢复修复。与当前状态模型兼容的组件、样式、环境变量、插件更新检测和工具卡改动按文件合入，其余保留现有实现。

## 冲突处理原则

1. 身份、授权和资源归属冲突时，以当前多用户实现为准。
2. 通用运行时、协议和安全修复优先适配后合入。
3. 上游新增功能如果引入第二套身份或存储边界，则先排除控制面，只保留可复用的底层接口。
4. beta 标签只用于差异审查，不单独产生提交或项目标签。
5. 合并记录、发布说明和代码行为保持一致，未启用能力必须明确标注。
