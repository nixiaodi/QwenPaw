# 2.2.0 功能覆盖、适配边界与优化建议

日期：2026-11-07。当前提交：`0e4b6ccbd21ca5f73e0d18df3b7a6a8dcbe54dfe`；对照上游：`refs/upstream-tags/v2.2.0` / `ae092fdca62164b467dee998893cbc450b97d59f`。

## 1. 分析口径与结论

本次以**当前工作区**为准，包含上一轮尚未提交的长回答渲染、个人资料库管理及权限接入改动。不是仅对照 HEAD，也不把旧分支中“merge 2.2.0”的标题当成当前已经升级的证据。

依据：[官方 2.2.0 发布说明](https://github.com/agentscope-ai/QwenPaw/releases/tag/v2.2.0)、该标签的中文发布说明和相关提交，以及当前前后端实现。状态表示源码覆盖情况，不代表生产环境或外部账号已验收。本轮只新增分析文档，没有修改业务代码、升级依赖、操作生产数据、提交或部署；没有重跑整套测试或进行并发压测。

**结论：适合按行为移植，不适合整版覆盖。** 对现有平台收益较大的，是流式处理、故障恢复、Embedding 切换与安全一致性补丁。Hub、统一模型平台、Mail/Data 和新版 Creator 涉及已有多用户授权、持久化或插件运行协议，必须另做适配。

当前也不是“完全没有 2.2.0 能力”：技能搜索/批量操作、模型与工具调用统计、会话项目目录覆盖、备份断开连接后继续执行等，已有相同或相近行为；应补差异而非重复开发。复制回复虽已有内容过滤，但还没有完整覆盖上游排除思考过程的修复。

此前 [上游同步分析](upstream-sync-analysis-20261106.md) 对 HEAD 与 2.2.0 的只读合并预演记录了 150 个冲突文件。这是 11 月 6 日的提交级预演结果，不是本轮包含未提交改动后的新测量，也不是功能缺失数量。

## 3. 优先移植的补丁与约束

### 3.1 服务端流式处理：继续完善长回答

上游 [#7239](https://github.com/agentscope-ai/QwenPaw/pull/7239)（`be908d881`）把文本和思考的反复字符串拼接改为片段收集，在需要完整内容时合并。[#7244](https://github.com/agentscope-ai/QwenPaw/pull/7244)（`504e81158`）把心跳改为独立轻量事件，避免重复序列化整个响应。

当前 `Envelope.heartbeat()` 直接产出 `_response`，而 `TaskTracker` 将 SSE 加入重放缓冲。由代码可判断，等待期间的心跳体积会受已生成响应影响；含大量工具结果或媒体时尤其值得改。这里没有做真实负载测量，不推断生产内存占用或承诺加速比例。

这与上轮前端优化互补，但仍需验证事件类型、序号、重连、部分响应保存和终态一致性。上游 [#7176](https://github.com/agentscope-ai/QwenPaw/pull/7176) 的 `useDeferredValue` 不宜直接叠加到已有节流组件；先测剩余卡点，再考虑历史卡片 memo 或导航改造。

另外，[#7448](https://github.com/agentscope-ai/QwenPaw/pull/7448)（`2bfe2b2b6`）是独立的小范围体验修复：当前 `extractCopyableText()` 未判断 `item.type === "message"`，且无正文时返回 `JSON.stringify(response)`。应按当前历史消息协议兼容处理，仅复制普通回复正文，无正文时不复制整包运行数据。

### 3.2 异常恢复：区分断流、无内容、清理未完成

上游 [#7150](https://github.com/agentscope-ai/QwenPaw/pull/7150)（`25af0963a`）新增首个有效内容等待、流中有效内容停滞检测以及超时后的清理状态。当前已经有重试和“输出后避免重复重试”等二开，不能整文件替换。

适配后应能区分：网络断开、服务端限流、模型无内容、工具等待、用户取消、流资源仍在释放。尤其不能把等待人工审批误判为模型卡住，也不能在工具已产生副作用后自动重放整个任务。

参考 [#7194](https://github.com/agentscope-ai/QwenPaw/pull/7194)（`e61348bc2`）补工作区启动失败/取消后的收尾。Driver 并发初始化 [#7174](https://github.com/agentscope-ai/QwenPaw/pull/7174)（`df67a01cd`）则需保留当前 `_runtime_errors`、凭据作用域和临时 Driver 管理；驱动同时启动也不等于用户任务已经实现真正并行。

### 3.3 Embedding：两个“范围”必须分开

当前已有“公共记忆/当前用户私人记忆”的资源范围。上游 [#7133](https://github.com/agentscope-ai/QwenPaw/pull/7133)（`eaf5c8a0d`）增加的是“全部/BM25/Embedding”的索引类型范围。二者应组合，不能用一个 `scope` 参数互相替代。

当前保存配置后设置 `needs_reindex`，但构建 ReMe 时仍按当前 Embedding 配置启用组件；没有看到以该标记统一关闭向量检索的完整链路。当前 `rebuild_index()` 也没有索引类型参数。值得补齐：

1. 明确显示正在使用的模型、已保存但待重建的模型，以及当前检索降级状态。
2. 保存切换前的可恢复配置；重建成功前使用 BM25，成功后再恢复向量检索。
3. 每个私人/公共索引分别保存状态和版本；公共索引完成不能把所有私人索引都标记完成。
4. 提供撤销切换、按索引类型重建、失败详情和重试；后台任务每次执行继续校验权限。
5. 验证结果可以跨页面保留，但须绑定登录身份、授权上下文、Agent 和配置指纹。当前 hook 在 Agent/configRevision 改变时清理状态，不能直接换成只按 Agent 缓存。

上游 [#7468](https://github.com/agentscope-ai/QwenPaw/pull/7468)（`03e103534`）允许未配置模型时启动不依赖模型的 ReMe 能力；当前启动顺序尚未覆盖。适配时只容忍“没有模型配置”，不应吞掉用户无权使用模型等错误。

这组修改处理记忆运行正确性，不自动带来个人资料库语义检索，也不等于召回质量评测或重排配置界面已经完成。

### 3.4 安全一致性：按现有有效策略适配

上游 [#7375](https://github.com/agentscope-ai/QwenPaw/pull/7375)（`5072269f2`）让治理扫描采用当前 FileGuard 路径设置，避免允许规则绕过敏感路径处理；[#7472](https://github.com/agentscope-ai/QwenPaw/pull/7472)（`c3d06ad9b`）统一处理 POSIX shell 续行，避免检查文本和实际执行文本解释不同。

当前 `GovernancePolicy._deep_security_scan()` 仍传 `self.sensitive_paths`；`run_deep_scan()` 前没有该上游续行规范化。另一方面，当前 FileGuardian/ToolGuard 已改用 `load_effective_security_policy()`。因此应该把上游修复接入**当前有效策略服务**，而不是复制回直接读取全局 `load_config().security` 的实现。

本次确认的是补丁覆盖缺口，没有执行攻击载荷，也没有证明线上可利用。验收应覆盖有效策略开关、自定义敏感路径、显式允许规则、单双引号、LF/CRLF，以及 Windows/POSIX 行为差异。

### 3.5 配置持久化：有价值，但不是替换数据库治理

上游 [#7135](https://github.com/agentscope-ai/QwenPaw/pull/7135)（`9a88d2ec1`）保护损坏的 envs 文件并原子写入。当前 `envs/store.py` 对 JSON 解析错误返回空字典，写入使用直接覆盖，因此具备明确改进价值。适配时继续保留加密、文件权限和启动环境白名单。

上游 [#6767](https://github.com/agentscope-ai/QwenPaw/pull/6767)（`37e7f6470`）强化共享文件系统上的 Agent 配置持久化。当前运行配置更新已有 `If-Match`、PostgreSQL 配置版本和路径锁，不能直接被上游文件版流程替换；应检查文件投影与数据库版本的一致性后补缺口。

备份 [#7283](https://github.com/agentscope-ai/QwenPaw/pull/7283) 对应的“连接断开仍继续”行为，当前 `platform_ops/backup_service.py:create_platform_stream()` 已有独立 worker 与 shield，并把数据库导出放在维护锁内。旧备份路由注释仍描述断开即停止，不能仅凭该注释判定功能缺失；后续验证应检查真实调用链。

## 4. 需要适配的较大能力

### 4.1 统一模型平台与缓存统计

上游 [#6302](https://github.com/agentscope-ai/QwenPaw/pull/6302)（`434574cb8`）涉及提供商目录、模型元数据、发现、能力路由和回退，是跨模块改造。当前已有自己的 `models/runtime.py` 授权复查，以及按可信主体聚合的用量服务。

建议分步接入：先统一模型能力与发现结果，再做受授权约束的候选回退，最后补思考控制及界面。模型不支持图片或工具时应给出可解释结果；自动回退不能越过用户获准使用的模型集合。

Prompt Cache 统计 [#7342](https://github.com/agentscope-ai/QwenPaw/pull/7342)（`2de79c1b3`）需要从提供商响应采集、运行消息、PostgreSQL 持久化、聚合到页面一起接入。当前基本统计已有，但没有对应缓存字段。未知或不支持统计应与零命中区分，不能只新增几个前端数字。

稳定提示词前缀 [#7346](https://github.com/agentscope-ai/QwenPaw/pull/7346)（`d0a688dc9`）可独立评估。当前环境提示中会话/用户信息位于可复用环境内容之前；调整顺序时保留当前私人目录和可信身份提示。缓存复用率需真实模型验证，不承诺固定成本收益。

### 4.2 Hub 与真实多人并发

上游 `hub/models.py` 中的 `RuntimeSpec/RuntimeRecord` 包含 `tenant_id`、`owner_user_id`、运行目录、凭据目录及实例生命周期。Hub 是运行实例控制面，与当前应用内共享 Agent 的权限模型不同。

直接引入会涉及重复登录、成员关系、会话归属、数据库/文件、运维和反向代理。若暂时保留现有平台，更合理的路径是先压测并查清共享状态，再逐步把用户或任务执行放到隔离进程/工作实例中，沿用现有授权入口。

当前技能配置仍存在执行期间修改进程环境变量的代码（`hooks/skill_env/skill_env_hook.py`、`agents/skill_system/registry.py`）。锁和引用计数不能单独证明不同用户凭据已实现进程级隔离；哪些业务链路会触达它，需要结合真实配置验证。本轮不据此断言所有用户任务都串行或存在已证实泄露。

会话项目目录也已有二开；上游多项目根改造中包含放宽部分工具目录包含检查、改由统一治理判断的变化，不能直接照搬到当前私人文件体系。

### 4.3 Mail、Data、Creator 与 Worker 协议

当前前端加载器仅接受 `frontend_runtime = "worker-v1"`。2.2.0 上游加载器仍用 Blob URL 动态 `import()` 执行前端模块。因此，上游新版应用不会自动适配当前隔离宿主，单改清单声明无效。

Mail 应额外定义邮箱凭据、收件范围、发信审批和后台监听生命周期；Data 应定义数据源、查询权限、分析任务与导出归属；Creator 应定义项目、素材、生成任务、密钥及费用归属。先让一个现有简单应用完成当前宿主协议闭环，再扩展复杂应用较稳妥。

2.2.0 的群聊共享、内置技能自动更新和统一扩展市场，同样必须沿用当前个人绑定、技能发布/授权和应用治理，不应通过引入上游入口绕过这些限制。

## 5. 对此前关注项的对应关系

| 此前关注项 | 2.2.0 能提供什么 | 仍需本平台补充什么 |
| --- | --- | --- |
| 新功能沿用现有权限 | 可参考功能实现 | Actor、Agent 角色、资源归属、凭据及执行时复查继续由当前平台统一处理 |
| 长回答渲染 | 历史渲染、过程折叠、服务端片段累计和轻量心跳 | 保留上轮组件、分页、终态刷新及迟到响应隔离 |
| 真实多人并发 | Hub 独立 runtime、Driver 并发初始化、会话多项目目录 | 真实负载、进程共享状态、取消与故障隔离、资源配额专项验证 |
| 异常恢复体验 | 模型停滞检测、超时透传、启动取消清理 | 当前授权/审批/重连状态下的统一提示和安全重试边界 |
| 依赖诊断 | Provider、运行时和启动错误改进可参考 | 当前已有 doctor 及若干检查；仍需把技能/插件的缺失依赖、版本冲突、未授权和运行未就绪区别展示 |
| 更新提示 | 内置技能及扩展更新机制 | 整个平台的版本差异、兼容提示、受控升级与回退不是同一功能 |
| 具体业务任务成功率 | Mail/Data 等能力、模型/媒体兼容和故障修复 | 真实业务样本、正确性/权限/可交付性验收；版本升级不能证明业务成功率 |
| 个人资料库页面管理 | 通用文件管理交互可参考 | 上轮管理已补；文件夹、复制、文本编辑、索引状态及 OCR 按需求继续完善 |
| 重排配置界面 | 上游重排代码整理可参考 | 当前已有 Reranker 配置模型和后端，表单、验证、凭据和降级状态仍需补 |
| 召回质量评测、失败原因 | Embedding 重建与降级状态更加明确 | 建业务问题集，区分无权限、未索引、索引失败、无相关结果及重排失败；记忆与资料库分别评测 |
| 自带前端插件适配 | 新应用和生态功能可作为目标 | 上游并未解决当前 Worker 协议兼容；必须做实际运行协议和数据归属适配 |

## 6. 建议实施批次及验收

| 顺序 | 范围 | 重点验收 |
| --- | --- | --- |
| 优先补丁 | FileGuard/续行一致性、envs 原子写入和损坏保护 | 保留有效策略和加密；失败不丢原文件；平台差异正确 |
| 第一批体验与稳定性 | 轻量心跳、流式片段累计、模型停滞检测、启动取消清理、复制仅含正文 | 长回答与工具密集任务；断开重连；终态完整；取消后释放；不重复执行已发生副作用的工具；复制内容不含隐藏过程 |
| 第二批记忆可用性 | Embedding 可撤销切换、按资源及索引类型重建、BM25 降级、验证状态、无模型启动 | 双用户私人/公共隔离；同维度换模型；失败可恢复；公共完成不误清私人状态 |
| 第三批日常交互 | 子会话分组/未读、过程折叠、按需求补文件操作、图片模型副本 | 未读属于用户；保留服务端分页；文件角色边界；原图可下载 |
| 第四批模型与观测 | 统一发现/能力元数据、授权回退、缓存统计和前缀优化 | 候选逐个授权；调用归属准确；指标不重复计数；依赖/协议兼容 |
| 独立专项 | Worker 应用适配、Mail/Data/Creator、真正执行隔离；Hub 单独决策 | 完整业务流程、多用户并发、任务恢复、密钥/文件隔离与配额 |

当前依赖声明为 `agentscope==2.0.4.post1`、`reme-ai==0.4.1.5`；2.2.0 为 `agentscope[model-ollama]==2.0.7.post1`、`reme-ai==0.4.1.10`，另增加/约束 MCP、邮件等依赖。这是声明版本比较，不是对生产安装环境的扫描。大功能移植前需要验证实际 API 和数据格式兼容；不建议先整体升级核心依赖再排查权限回归。
