# 本地首屏与会话性能优化设计

用户已确认本地实施诊断报告中的四项优化；验收前禁止 Git 提交、推送、部署和任何线上修改。保持当前工作目录，不创建分支。测试使用本地服务、模拟数据和独立测试数据库。

## 方案

采用按需加载与有界历史接口。只压缩传输不能减少解析和重复请求；只加浏览器缓存不能改善新会话和大工具输出，因此同时处理首屏、请求、传输和渲染四层。

- 首屏移除全站页面预加载，页面在访问时注册到插件模块表；Monaco 初始化移入编辑器所在模块，插件公共依赖保持兼容；身份、插件和路由等待期间显示加载状态。
- 普通会话的空消息检查使用轻量元信息，不拉取历史。聊天 UI 首次只加载最近五个完整用户轮次，向前使用 sequence 游标。未传分页参数的旧接口继续保留完整历史语义，模型上下文和消息事实不改变。
- 分页边界落在用户消息处，保持用户输入、工具调用及输出属于同一页；忽略已失效消息，最近页保持最新消息编辑语义。页面内保留前后顺序，重复消息按稳定 ID 去重。
- 大于 16 KiB 的工具输出返回简要占位、工具身份及受保护的读取引用；点击后才请求完整结果。完整输出仍保存在原位置，不做删除或业务数据迁移。现有旧版外置载荷允许先还原再提取头信息以保持兼容。
- 普通与管理员输出接口复用原有权限边界。必须验证消息属于已授权会话和目标智能体，成员不能调用管理员接口，分享会话仍只读。
- 管理员详情默认只返回分页聊天数据；原始记录切换后独立分页获取。聊天页和详情提供加载更早消息、失败重试及加载状态。

## 验证

先补回归测试并确认失败，再实现。覆盖页边界、无消息、编辑替换、重复请求、跨用户/跨智能体拒绝、延迟响应、完整输出展开。以 321 条记录、单条输出 2 MiB 的合成数据比较初次传输和请求次数；构建核对首屏不再同步包含 Monaco，浏览器验证首屏、编辑器、普通/管理员历史翻页和输出读取。

无需新增依赖和数据库迁移。保留本地配置与用户现有未跟踪证书目录。
