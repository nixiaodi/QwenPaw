# 消息编辑、附件、应用可见性与模型断流：阶段优化总结

日期：2026-10-14。阶段基线为 `b8c69f52`。用户已授权将本阶段中文总结和代码提交、推送，并发布到现有服务器；此前仅在本地测试。本总结描述本阶段新增及补修，不重复列入上一提交已有的频道、记忆、认证和 imagegen 2.5 更新。

## 最新用户消息编辑

- 最新用户消息的复制按钮旁增加编辑入口，历史用户消息不开放编辑；只读或不支持修订的会话不显示入口。
- 原位修改文本，支持取消、重新发送、Escape 取消、Ctrl/Cmd+Enter 发送。等待启动、生成中、停止后和完成后使用相同入口；取消编辑保留原回答，确认重发才停止原任务。
- 保持原会话、智能体、模型与审批设置，保留原图片、文件等附件。编辑时展示原附件；重发首帧同时建立文本和媒体卡片，无需等待模型配置查询，也不重复上传。
- 普通提交与编辑提交使用会话提交锁；服务端校验真实用户、会话归属、最新消息和请求版本。新用户输入先持久化，再启动后台执行，避免刚发送就无法找到修订目标。
- 原轮次保留审计并退出有效历史；恢复执行前的 JSON 上下文和 Scroll 历史边界，清理旧轮次的有效检索记录。保存操作携带运行版本，避免被停止的旧任务覆盖新上下文。
- 修订请求使用确定的运行 ID：重复请求附着当前执行或回放已结束结果，避免重复调用模型；回放不再误插入空响应。
- 切换会话或智能体时清理待发送编辑，旧请求的延迟完成不得修改新会话。

## 旧会话兼容与重启边界

旧会话可能没有执行前快照，运行时还会在附件后插入上传路径说明。恢复时只排除紧邻媒体、路径与原附件一致的系统说明，用户原文仍须完整匹配。不同路径、额外用户文字和非相邻说明不会被忽略；无法可靠恢复时明确报错，不清空或猜测旧上下文。

前端区分最新消息冲突、旧上下文无法恢复及中断运行无法继续，保留草稿并给出对应提示。

提交前复审另外补齐两项边界：已有修订的替换消息必须仍为最新有效用户消息；运行任务丢失后，仅数据库状态仍为 queued 且审计恰好包含两条初始接收事实的请求可以首次启动。已经开始执行、等待审批或有执行事件的孤立请求拒绝自动重跑，防止重复工具副作用和回滚较新对话。

编辑只替换文本，原附件保留；已经发生的文件写入、发信、外部 API、记忆写入等真实效果不会随旧回答隐藏而自动撤销。

## 通用附件上传

上传入口改为文档、图片、视频、音频等通用文件说明，去掉依据模型原生多模态能力产生的“只支持图片”提示及警告。沿用上传大小限制、原附件归属和访问校验，不放宽跨用户文件权限。

## 应用安装可见性

修复应用已成功安装、加载，但“我的应用”仍为 0 的默认授权衔接错误。路径、市场 URL 和 ZIP 安装未指定授权范围时，首次安装仅授权真实安装者。

显式授权设置继续生效；未指定范围的重装和升级保留已有指定用户、全员或明确空范围。在同一数据库事务和安装行锁下更新安装事实及授权，避免并发重装覆盖授权。

这项修复调整应用的安装可见性与授权默认值，不改变应用内部业务数据的隔离方式，也不会向全部用户开放已安装应用。

## 模型断流与运行状态

统一模型调用层识别没有 HTTP 状态码、由基础 OpenAI APIError 表达的未完成流。工具参数在该次模型响应完成前暂存；失败时丢弃该尝试的 ID 和增量，只按现有次数与退避配置重试当前模型子请求，此前执行完成的工具不重新执行。

成功后透传原顺序的全部增量和完整末帧，兼容真实 AgentScope ChatResponse、ChatUsage 和复用可变响应实例的情况。普通文本首帧继续即时输出；已显示文字或思考内容后遇到这类断流，不拼接另一次尝试。取消不重试并释放资源，重试耗尽仍明确报告失败。

错误提示读取真实模型属性，避免有效模型显示 unknown；最终 response 的 failed/cancelled 状态正确写入 PostgreSQL，覆盖此前已完成的消息状态，避免整轮被误记为成功。单个工具失败不等于整轮运行失败。

本地历史日志中认证不可用与缺少 response.completed 属于不同错误。现有证据无法确定后者由网络、代理还是上游服务内部中断造成；本次修复恢复及记录机制，不承诺外部模型永不发生断流。本地 8 个启用智能体均使用同一修复层，当前默认都指向 cpa / gpt-5.6-sol。
