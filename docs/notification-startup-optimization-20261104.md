# 本地追加优化：通知请求与登录入口

本轮在此前面板请求、SSE 和工具输出修复基础上继续优化。范围仅为本地前端源代码及 `console/dist`，未提交、推送、部署或访问线上；未更改数据库结构、历史记录或后端业务代码。

## 修复内容

### 1. 通知与审批共用读取

- 侧栏、聊天通知、桌面通知复用 `useConsolePush`，同一用户/智能体/会话范围只有一个在途推送请求。保留 2.5 秒的前台间隔，隐藏页面为 30 秒，离线暂停，失败退避。
- 订阅采用引用计数：某个界面卸载不会取消其他界面的读取；最后一个界面离开后才释放请求和监听器。用户、登录代次、智能体或会话变化后，清空旧快照并取消旧请求。
- 后端带 `session_id` 的接口会消费消息，无参数接口则查询近期消息。只有通知展示组件订阅后才启用会话消费；只显示徽标时保持非消费读取，防止界面尚未就绪就取走消息。
- 审批列表在两种查询里都是当前用户的全部待审批数据，因此可以共享。侧栏的单条未读查询、收件箱的完整分类列表、桌面的未读分类列表仍保留各自参数，不混用不同范围的返回值。
- 响应内容未变化时保持同一快照，不再通知所有组件重复渲染。

### 2. 收件箱和桌面通知不再堆积请求

- 两处 `setInterval` 网络轮询改用已有的 `schedulePolling`，上次完成后才计时下一次；隐藏/离线暂停，重新显示后恢复。
- 收件箱按钮刷新与轮询共用在途请求。修复前，18 秒慢响应叠加两次手动刷新共发起 6 个请求；现在为 1 个。桌面通知 36 秒慢响应原有 4 个请求，现在为 1 个。
- 已读、全部已读、删除会取消过时读取，并阻止迟到响应恢复旧内容；写入过程中不启动新的列表读取。部分删除后立即重新获取剩余项目，不等待旧请求超时。
- 切换身份和卸载会取消在途读取；旧账号的数据不能回填到新账号界面。桌面通知同时清除旧身份的历史、提示和计数。

### 3. 插件完整依赖离开匿名登录入口

- 将插件注册表单例提取到轻量的 `pluginSystem.ts`；原 `hostExternals` 仍重新导出同一个单例及类型，保留旧插件入口兼容性。
- `main.tsx` 不再同步初始化整套 antd、图标和插件 SDK。认证通过后，插件列表读取与宿主模块加载并行；宿主及 SDK 准备完成后才执行插件脚本。
- 完整组件、836 个图标导出、菜单、路由、工具渲染及聊天扩展接口均保留。没有手工拆分 vendor，也没有删减插件可用的 API。
- 可信宿主模块准备最多等待 8 秒；取消身份或超时会结束当前等待。动态 import 本身无法取消，后续完成只初始化全局可信宿主；已取消的调用不会继续执行用户插件。

## 验证

- 前端相关 28 个文件、231 项测试通过，覆盖此前队列所有权、身份隔离、面板/SSE、插件注册与本轮通知路径。
- TypeScript、修改范围 ESLint、完整构建、Monaco CSS 检查和 `git diff --check` 通过；保留已有的大包和第三方循环依赖警告。
- 本地实际服务的健康、认证状态、版本接口正常，提供的入口文件与当前构建逐字节一致。匿名 Chrome 登录表单冷打开约 0.406 秒、刷新约 0.103 秒，深链接正确回到登录，无页面脚本错误。
- 构建页面加合成 API 验证：通知接口挂起 10 秒时只有一个有效在途请求，响应后提示只显示一次；智能体初始化引起的已取消请求单独计数，不当作在途请求。
- 宿主 JS 资源被人为挂起时，8 秒等待上限生效，基础页面可以继续显示；插件列表挂起仍由已有 8 秒网络超时处理。
- 合成插件实际在 Chrome 中执行：检查完整 antd、图标和聊天 SDK，再注册菜单路由及工具卡片；注册页面正常显示。普通聊天、管理员历史和大工具输出浏览器回归正常。
- 本轮没有修改后端，未重复执行上轮已通过的 198 项后端聊天测试；也没有真实模型调用、真实账号并发或生产验收。

## 复核后仍待处理

1. 会话列表首次及变化后仍全量返回。侧栏与抽屉在完整数组上做搜索、置顶排序和当前会话定位；服务端分页应连同这些语义一起调整，不能直接截断为前几十条。
2. 第三方插件脚本执行仍可能无限等待顶层 Promise，或同步占用主线程。本轮处理的是完整宿主依赖的加载位置及其等待上限，并没有宣称能中断任意插件 JavaScript。下一步需设计执行隔离和迟到注册清理，避免单纯加超时后遗留跨身份副作用。
3. 超长聊天正文、Markdown 和代码块的主线程渲染成本仍需真实长会话测量；现有测试不能代表所有用户设备和并发负载。
4. Nginx 静态资源直出尚未实施，线上配置未检查或修改。
