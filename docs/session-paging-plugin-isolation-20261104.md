# 会话分页与前端插件执行隔离：本地实现与复核

## 范围和授权

延续本阶段本地性能优化，处理会话列表分页和插件同步代码阻塞主页面的问题。用户明确选择严格隔离：旧前端插件必须升级，停止自动执行。

本轮没有提交、推送、部署或访问生产服务器，没有迁移数据库结构或修改线上数据。保留工作区此前尚未提交的优化。

## 会话列表

- 新增 `/api/chats/page`，默认 20 条，上限 100 条，返回 `items/has_more/next_cursor`。侧栏、聊天会话抽屉、会话管理均按需加载；管理员全部会话采用数据库游标分页。
- 标题搜索、归档、频道、用户筛选及 owned/shared 权限范围由服务端处理，避免只搜索当前已加载记录。置顶优先，更新时间和 ID 作为稳定排序键。
- 游标绑定账号、智能体及筛选条件；每页重新检查 PostgreSQL 授权。运行索引缓存不保存授权结果，分享撤销不依赖缓存过期。
- `chats.json` 运行索引在文件标识、大小或时间变化时失效；首次解析及排序移到 IO 工作线程。分页用二分定位游标，候选授权每批最多 200 条，只投影本页状态。
- SDK、侧栏和抽屉合并相同的在途分页请求；单个组件取消不影响其他读者，全部读者离开或身份变化才取消共享网络请求。
- 只刷新已经加载的页，不自动扫完全部历史。切换条件取消旧请求，立即清空旧结果，迟到响应不能替换新结果；失败保留当前页并提供重试。
- 旧 UUID 深链接通过 `/api/chats/{id}/spec` 获取单条元数据；旧临时会话链接及首条消息解析使用精确 `session_id` 查询，避免被第一页边界截断。
- 删除后刷新已加载页；仅删除当前会话时跳转，不再把“当前会话不在第一页”误判为已删除。

兼容性：旧全量 `/api/chats` 接口保留，当前页面已迁移到分页接口。没有引入数据库字段或迁移。运行索引文件变化后仍需解析该文件；本轮没有声称运行索引已经全面迁入数据库。大量无权限候选项、持续变动的排序和真实多用户并发仍需要实际容量数据评估。

## 插件执行

- 前端入口必须明确声明 `entry.frontend_runtime = "worker-v1"`，缺省为 legacy。旧前端不执行并显示升级提示。
- 入口导入、渲染函数及事件处理均在独立 Worker。主页面仅接受有限的路由、工具卡片和界面数据；无主线程执行回退。
- 初始化、渲染、网络请求都有超时；死循环通过终止 Worker 处理，超时不会留下继续运行的插件。账号切换会清理旧 Worker 和注册项。
- 基础页面不等待插件加载，避免插件清单慢、脚本慢或无限顶层等待阻塞菜单和聊天。
- 对界面数据、插件参数、注册数量和代理请求并发做有限额的校验，集中在协议层和客户端实现，避免每个页面重复处理。

迁移接口、示例及边界见 [worker-v1 迁移说明](frontend-plugin-worker-v1.md)。当前协议不再提供旧的任意 React/DOM 注入功能；这属于用户已选择的兼容策略。Worker 是执行隔离，不是恶意代码安全沙箱。

## 本地验收

使用 http://127.0.0.1:18089/login 登录本地服务，检查：

1. 侧栏和会话管理点击加载更多、搜索早期会话，切换智能体与归档/分享筛选。
2. 管理员全部会话切换智能体，继续加载和搜索，打开只读详情。
3. 刷新旧会话链接，删除其他会话后确认当前聊天仍保留。
4. 如安装旧前端插件，确认出现升级提示；升级后的 Worker 插件正常使用，故障提示不阻挡基础页面。
