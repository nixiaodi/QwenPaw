# 聊天图片预览权限误判核验（2026-10-13）

## 已确认的系统原因

用户报告会话 `REDACTED_UUID_1` 的两张图片预览失败。

数据库显示图片附件属于该会话所有者、归属于 `designer` 智能体、生命周期为 `temporary`，磁盘文件存在。附件下载接口能够按 UUID 和上传者身份返回图片。

错误来自两套不一致的规则：

- `_resolve_console_upload_dir` 只把普通使用者的上传放进个人空间；智能体所有者和协作者的上传仍放进公共智能体 `media` 目录。
- `/api/files/preview` 在多用户模式中仅允许当前用户的 `user_workspaces`，并未核对旧 `workspaces/<agent>/media` 文件的有效附件归属。

因此，同一文件可以通过附件接口下载、也可以被后台工具读取，却在工具卡按本地路径预览时返回 403。这是平台路径与附件归属校验未统一，不是图片所有者错误，也不是 Windows 文件读取权限问题。其他智能体所有者、协作者走同一上传分支时同样受到影响。

## 通用修正（本地源码）

1. 所有多用户聊天上传统一按当前可信用户、智能体解析个人附件目录，不随智能体编辑角色变化；上传和保存附件共用目录解析函数。单用户模式保留原有配置目录。
2. 旧智能体附件目录中的文件，仅在实际路径、当前用户、智能体和有效附件记录全部匹配时允许预览。支持已保存的历史附件目录，不将整个智能体目录开放。
3. 保存、移动、删除附件沿用上传者身份验证，兼容历史上传和保存目录；保留敏感路径保护，并在解析前拒绝符号链接及 Windows junction。

没有按会话 ID、图片文件名添加特殊放行，没有改写该会话，也没有搬移原图片。

## 验证与生效状态

- 48 项相关单元测试通过，包括所有者、协作者、普通使用者上传隔离；旧附件本人 GET/HEAD 预览；他人、未登记、已删除、错误智能体、非附件目录和符号链接拒绝；历史保存目录兼容。
- 独立 ASGI 测试进程使用真实 PostgreSQL 附件记录及用户报告的两张原图，GET/HEAD 均返回 200，返回文件内容与原图一致；其他用户返回 403。日志为 `build/preview-live-20261013.log`。
- 单元测试日志：`build/preview-regression-20261013.log`。
- 在用户明确要求“重新运行服务验证效果”后，本地服务已重启加载修改，状态为 `ready`（PID `53372`）。没有部署服务器。
- 真实运行服务验收日志为 `build/preview-running-20261013.log`。两张原图使用认证请求和浏览器图片所用的查询令牌方式，均返回 200，文件内容一致；未登录请求返回 401。
- 当前 8 个启用智能体均逐个通过真实 HTTP 验证：`default`、`QwenPaw_QA_Agent_0.2`、`tendering-and-bidding`、`designer`、`news`、`new-media`、`ppt-creator`、`contract-review`。每个智能体的临时 PNG 上传进入该上传者的个人 `media`，预览、附件下载、保存及保存后预览全部返回 200。
- 两次验收产生的临时测试附件均已按确切的测试附件 ID 清理，临时测试登录会话单独撤销。没有删除或改写用户的原图片和会话内容。

修正已在本地生效，已验证的角色和目录场景能避免这次权限误判。真正不属于当前用户、被删除或不能安全读取的文件仍会被拒绝。不能将此结论扩大为所有类型的预览问题都不可能发生。

另有独立的模型输入大小问题：其中一张 PNG 为 2,412,788 字节，超过 `freeze_local_image` 的 2,097,152 字节限制。该限制影响模型读取图片，不是浏览器预览接口返回 403 的原因；本次没有改动模型图片大小限制。
